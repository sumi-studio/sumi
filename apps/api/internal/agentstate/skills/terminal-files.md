# 共有ターミナルとファイル

## 同じセッションを使う

人と秘書が同じターミナルの出力を見て、同じプロセスへ入力できます。
`terminal.list` で既存セッションと状態を調べ、`terminal.open` で必要な
新しいセッションを作ります。画面への接続が切れても実行環境が生きていれば
プロセスは続きます。実行環境自体を失った場合に、プロセスがそのまま復元
されるという保証ではありません。

## 入力と出力を追う

`terminal.write` はキー入力を受け付けます。コマンドを実行する改行も入力の
一部です。返却時の `intended` は配送待ちを表し、実行完了を意味しません。
`terminal.inputs` で `written`・`failed`・`unknown` などの配送状態を、
`terminal.read` で出力とセッションの状態を読めます。入力を表示しない
プログラムもあるため、エコーがないだけで未配送とは判断できません。

`unknown` では一部がすでに入力された可能性があります。新しい入力を送ると
別の操作になるため、元の操作を繰り返す判断には現在の画面やプロセスの状態が
関わります。人が操作を独占している間は秘書からの入力は拒否されます。

出力を続けて読む場合は `next_cursor` と `event_cursor` の両方を引き継ぎます。
欠落を示す gap や loss marker は、読める履歴に欠けがあるという情報です。
欠けた出力を見たことにはできません。

## プロセスやセッションを止める

`terminal.signal` は現在のフォアグラウンドのプロセスグループへシグナルを
送り、`terminal.eof` は EOF を送ります。対話プログラムの入力待ちと、シェルの
プロンプトではその結果が異なります。`terminal.close` はセッション全体を
終了します。

## ファイルを読む・書く

`file.list`、`file.stat`、`file.read` は秘書のワークスペースのファイルを
扱います。パスはワークスペース相対です。ファイルの版は `version` に返り、
`file.write` の `expect_version` へ渡すと、その版から変わっていない場合だけ
上書きします。新規作成は `expect_version: "none"` です。

テキストとバイナリの選択、読み取りのページ指定、サイズ上限は各ツールの
定義を参照できます。Messaging への添付投稿は別の操作で、ファイルを書いた
だけで会話へ共有されることはありません。
