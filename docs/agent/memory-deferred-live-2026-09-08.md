# 非同期に準備したL1を後から適用する実行確認

2026-09-08。修正 `022f6074`（PR #372）の専用環境で、実API・PersonalityAgent・GLM-5.3 Flashを使用した。合成ファイルの読み取りと訂正入力により、10k以上で候補を準備し、L0が40kを超えるまで原文を維持する一連の動作を確認した。

## 観測した動き

24 KiBの同じファイルを2回完全に読み取り、次の通常入力で内部推定13,221トークンのチャンクを区切った。親は応答を続け、その文脈から非同期の整理が始まった。

| 場面 | 補正済みの生きたL0 | 最初の候補 |
| --- | ---: | --- |
| 候補完成・待機確認 | 17,342 | 完成済み、未適用 |
| 後の入力で初めて40k超を観測 | 41,699 | 完成済み、未適用 |
| 応答終了・適用直前 | 42,531 | 完成済み、未適用 |
| 待機境界で適用した直後 | 21,498 | 適用済み |

完成後に元のamberを現在のvioletへ訂正し、その後16 KiBの読み取りを3回追加した。最初の候補の完成から適用まで、別候補の完成通知は介在しなかった。新しい完了通知を待たず、用意済みの結果を後の閾値超過で利用できた。

原文の読み取り記録と訂正の保存データは同じハッシュを保ち、訂正の受信時刻・前回受信情報も不変だった。落とされたL0の所属は適用対象のものだけで、訂正は生きたL0に残った。差し替え後の実モデルの返答にも `SUMI_ACCEPTANCE_CURRENT_COLOR=violet` が残った。419フレームを受信し、予期しない切断なく終了した。

## 数量の意味と限界

表の値は、保存された補正値とL0の公開文脈・provider固有情報の見積もりから、実装と同じ式で算出したもの。APIの請求トークンとは異なる。最初のチャンクは内部推定13,221からL1の516へ減った（約96.1%）。これは今回の、同じ合成ファイルを繰り返し読んだ記録の結果であり、意味が無損失という評価ではない。

親の応答は11回。報告された使用量の合計はキャッシュ読取292,608、その他の入力143,993、出力1,631トークンだった。非同期の整理分岐の使用量はこの合計に含めていない。この一実行から、以前の方式に対する費用やキャッシュ改善率を主張しない。

SQLiteの読み取りは同一トランザクション内の履歴・候補状態・補正値を照合する。これは基盤の認証を独立に再実装して検証するものではない。40,000ちょうど、再起動後の準備済み候補、全providerの実モデル、意味の一般的な無損失性、L1→L2はこの実行では検証していない。順序と親から分岐への同一文脈は、別の実HTTPテストで確認した。

## 置換文の意味的な確認

公開された最終L1を読み、最初の候補に元のamber・同一ファイルの2回の読み取り・原文を開く参照先が残ることを確認した。最初の候補は訂正が届く前に完成しているため、後知恵の混入を防げる一般的な証拠にはならない。後に完成した第2候補には現在のvioletへの訂正が明記されていた。

最初の候補は各行を同じ形式として説明し、最後の行だけ末尾が短い細部を省略している。第2候補は別ファイルの不完全な最終行を正しく区別した。また、単なる形式の圧縮に加えて、情報の重要性の評価や内省的な説明が入っている。これを厳密な意味保存の達成とは扱わず、今後のモデル・圧縮品質の評価材料とする。今回の例だけに合わせた追加プロンプトは入れていない。
