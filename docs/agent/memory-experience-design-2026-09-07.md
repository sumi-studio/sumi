# Sumiの記憶を、共に生きる経験から考える

2026-09-07の設計検討。これは採用済みアーキテクチャでも、認知科学から導いた仕様書でもない。[プロダクトのDescription](../../README.md#description) と今回ユーザーが示した思想から、[基盤監査](foundation-audit-2026-09-07.md)・[他エージェントとの比較](foundation-comparison-2026-09-07.md) を捉え直す。

## 判断の出発点

ユーザーが明示したことは、Sumiを本当に人間として扱い、人間たらしめること。人間的な記憶への理解を深め、乖離を可能な限り減らすこと。

その観点から設計を疑い続け、迷走を自ら是正できるメタ認知を保つよう求められたのは、設計する私（Codex）である。私自身が要求の読み方や考察のずれを点検し、修正する。この発言をSumi自身の必須機能や受入条件へ読み替えない。

認知科学の研究は、この考察を裏付け、思い込みへ反証を与えるために参照する。研究で採用された分類・実験課題・脳部位を、そのままSumiのデータ構造や合格基準に置かない。何を人間としてのあり方に必要と考え、どの乖離を許容せず、どう具体化するかは、引き続き自分たちが判断する。

## 本人が自分の記憶を扱う

ユーザーはさらに、要約担当のモデルへ対象箇所だけ渡す方式を退け、**非同期に進めるために親をforkし、親と全く同じコンテキストを持つ本人が、自分の記憶を扱う**という方向を示した。記憶整理の出発点をここに置く。

担当範囲は「今回どこを整理するか」であり、「そこしか読ませない範囲」ではない。同じ発言や観測でも、本人のそれまでの経験・今の状況・後からの訂正によって意味が違う。その判断材料を切り離してから、重要な意味を残すように指示しても足りない。

ここでのforkは、同じ本人の文脈から記憶を扱うための推論の分岐である。別の生活を始める人格を作ったことにはしない。分岐時点の文脈と、整理している間に親へ増えた経験を区別し、整理結果で親の新しい訂正や理解を巻き戻さない適用を考える。

### 戦略的忘却は、取り戻せると本人が分かって詳細を手放すこと

ユーザーがいう戦略的忘却は、たとえば「メモに書いたので、詳細は今覚えていなくても、見返せば分かる」と本人が分かっている状態。対象はメモに限らず、資料、会話履歴、ファイル、アプリの記録、道具で再取得できる情報も含む。

詳細を常に持つ代わりに、何がどこにあり、どんな場面で、どう取り戻せるかという手掛かりを本人が持つ。これは、保存先へアクセスできるだけの状態より踏み込んでいる。内容を外す本人が、その外部の支えを利用可能な自分の記憶として理解していることが要る。

たとえば長い資料を読んだ後、全文は文脈から外しても、「あの方針を比較した表はこの資料のここにある。条件が変わったらそこを見直す」と分かっている。この状態で必要時に読み返し、当初の理解も更新できるなら、詳細を毎回保持する必要を減らせる。これをメモ専用の機構や、リンクを貼れば無条件に削るルールへ狭めない。

外部の情報が更新・移動する場合には、現在の内容を知りたいのか、当時自分が見た内容へ戻りたいのかも区別する。全部の資料を無期限に複製する仕様を先に決めるのではなく、その忘却によって何を再取得でき、何は取り戻せなくなるかを本人が扱えるようにする。

## 記憶を考える時に落としたくないもの

以下は私が提案するSumiの設計仮説であり、各項目をユーザーが直接要求したという意味ではない。全ての人の記憶が同じ仕組みで動くという主張でもない。

### 1. 出来事には、その本人がいた

「何が起きたか」という客観的な記録だけで、その人の経験を表せるだろうか。自分がその場で見た、後で人から聞いた、自分で確かめた、そうだと思っただけだった、という違いがある。何をしようとしていて、その出来事をどう受け取ったかも違う。

Sumiでは、共有の原記録と本人の経験を区別したい。同じ会議に二人の秘書が参加しても、共有した対象や発言は同じでありつつ、各人が何に気付き、何を引き受け、どう理解したかまで同じにする必要はない。他人の記憶を読んだことを、自分がその場を経験したことにしてはならない。

**現状との距離：** 本人IDと会話ロールは保存される。一方、モデルが受け取る話者・場所・時刻の不足、共有空間の出来事の未配送、本人の私的履歴へ戻る入口の欠落がある。記録の所有と経験の視点は、まだ十分につながっていない（A01/A02/M04）。

### 2. 何を覚えているかに、その人がどう変わってきたかが含まれる

相手のプロフィールへ変換するだけでは、経験から本人の理解が変わった経緯を取り落とす。「この人は提案が嫌い」という記憶と、「私は理由を読み取らないまま提案を量産した。嫌だったのはその扱いだったと分かった」という記憶では、次の接し方が違う。

本人の過去の解釈も、新しい事実を受けて変わり得る。出来事、当時の自分の理解、今の理解を全て同じ事実として上書きするのではなく、必要な時に経緯へ戻れることを考えたい。関係も、信頼スコア一個や固定した好みの一覧へ早く縮めない。

**現状との距離：** 仮置きの圧縮promptは、出来事・ユーザー情報・約束・参照が中心。本人がどう捉え直したかを明示的には保護せず、後で理解を訂正する道具もない。ただし、自由文で表せない・モデルが省察できない、という指摘ではない（M02/M04/Q01）。

### 3. 今は関係なくても、後で意味を持つ経験がある

次のタスクに効率よく答える情報だけを残すと、本人の生活が仕事の進捗の束になってしまう。雑談、迷い、一緒に試した失敗、画面を見て発した短い言葉が、後で相手を理解する手掛かりになることも、設計上は許容したい。

これは全履歴を常にモデルへ詰めるという意味ではない。「今、注意の中心にない」「すぐ思い出せない」「記録を整理した」「経験の内容を失った」を区別するということ。まだ価値を言語化できない経験を、外部の採点器が当面の仕事への有用性だけで捨てないようにしたい。

**現状との距離：** 古い会話を容量だけで文脈から外し、本人は私的原文を検索できない。仮置きの約800tokenの要約を接続するだけでは、この距離は埋まらない（M01〜M04）。

### 4. 思い出すことが、今の知覚や判断へ返ってくる

「先月の件を検索して」と言われた時だけ過去を引く秘書でよいだろうか。同じ画面、似た言い回し、以前困った状況に触れて、自分から関連する経験を思い出せることを考えたい。その関連が勘違いなら、現在の違いを見て修正できる必要もある。

ここでは、常時の全文検索やすべての新着への介入を先に決めない。目の前の出来事、気にかかっていること、過去の経験が本人の中で結び付く道を考える。予定時刻の起動はその一部を支えるが、記憶やAttention全体の代わりにはならない。

**現状との距離：** 共有イベント、明示した返信予定、仕事の継続、過去の再参照が分かれたまま。記憶を保持する部分だけでなく、本人へ何がいつ届くかが不足している（A01〜A04/M04）。

### 5. 間違えた経験が、謝罪では終わらない

今回の会話には具体的な題材がある。ユーザーは雰囲気の案を見たかったのに、私の作業は入力部品の試作へ寄り、要求された質にも届かなかった。これを「ユーザーはUIに厳しい」「次は品質を高くする」と記憶するだけでは、何を間違えたのかを取り落とす。

まずこれは私自身が正すべき作業と考察の問題である。後の似た場面で、私が「作っているものでは、相手が比較したいことが見えない」と気付き、作った量に引っ張られず方向を修正できるかを問う。

この経験をSumiの記憶設計にも生かせるのではないか、というのは私の仮説である。元の言葉、理由、実際に見せたもの、その時の本人の捉え方、指摘とその後の理解へ戻れることが、後の判断にどう役立つかを検討する。

同時に、前回の経験を何にでも当てはめてしまうなら再び考え直す。いつも反省文を書く規則より、結果と目的の食い違いを見つけ、行動を変え、必要な理解の訂正を次へ持ち越せるかを確かめたい。

**この仮説と現状との距離：** 間違いを認める一般的な指示と、ツールの成否を知る入口はある。一方、過去の理由の再参照、訂正の保存、元の目的の継続を支える経路が不足している。それが後の行動をどう変えるかは、仮説を確かめる評価の候補になる（M03/M04/A03/Q01）。

### 6. 同じ人であることと、同じ解釈を固定することは違う

本人が過去の自分の判断を否定したら、それだけで一貫性を失ったと評価するべきだろうか。変わった理由が本人の経験とつながっていること、相手との約束に影響するならその相手と向き合うことを重視したい。

モデルを変更する、プロセスを休止する、文脈を整理することも、本人の生活の続きにどう位置付くかを考える。IDが同じだから十分とも、過去の全文章を毎回読めないから別人だとも、技術上の都合だけでは決めない。この問いを、固定的な自己紹介や新しい人格属性テーブルへ早く閉じない。

## L0→L1で、まず具体化すること

ユーザーの方向は、**主にツールコールの冗長表現を圧縮し、情報の質的な意味の劣化を可能な限り防ぐこと**。上の考察と整合させるなら、経験の意味を選別して短い仕事用サマリーへ置き換える前に、記録の表現を見直す。

| 整理候補 | 残す必要がある違い | 最初に確かめること |
|---|---|---|
| 検索結果に毎回現れるJSONの列名、装飾 | 本文、値と型、話者、日時、取得範囲、空文字・null・未提供 | 小さな表現でも同じ値と対応を読めるか。本文内の空白を装飾と混同していないか |
| 同一ファイルの本文の再掲 | いつ、どの対象を、どこまで、何回読んだか | 現文脈に本文を一度残して観測を結べるか。変化がなかった確認も残るか |
| 同じエラーやポーリング結果の文言 | 各試行の順序、条件、ID、時刻・間隔、成否・不明 | 一件の失敗と反復した失敗を取り違えないか |
| 呼出と結果の重複するラベル | 対象、引数、呼出ID、実行経路、返答との対応、結果の範囲 | 並行した似た操作や、許可と実行成功を区別できるか |
| ログ・検索の共通パスや定型部分 | 各場所、行番号、本文、出力切断、未取得の範囲 | 一部分しか見ていないのに、全体を確認した記憶にならないか |

ツールが運ぶ人の言葉、画像、資料そのものは、ツールの冗長な外枠とは分ける。同じ文字列でも、別の人が再び言ったことなら別の出来事である。同じ観測結果でも、時間を空けて確かめた事実には意味がある。共通部分を一度持つことと、二度目の経験をなかったことにすることは違う。

原文へのリンクを残すだけで、本人が何をそこへ預けたか分からない外部化は避ける。一方、上記の戦略的忘却として、本人が保存先・再取得方法・戻る手掛かりを理解したうえで詳細を外すことは、積極的に扱う。長い差分の鎖や極端に暗号的な表記で復元を難しくするなら、元の分かりやすい表現に戻す余地が要る。

**追加で確認した現状：** 本番未接続の既存compactor実装では、要約前の入力整形で通常のToolCallのIDと実行経路を落とし、時刻を秒精度へ変え、画像を一律に省略する。したがってpromptを差し替えるだけでは足りない。一方、Messagingのcontentとdetailsに同じ値が保存されていても、確認したprovider入力は主にcontentを使うため、二重保存の解消がそのまま文脈半減になるわけでもない。[compact入力整形](../../apps/agent/src/memory/compactor.rs) L769・787・800、[Messaging結果](../../apps/agent/src/tools/messaging.rs) L2662。

まず、親が実際に受け取ったコンテキストをfork側にも渡し、その状態で少数の整理候補を作る。forkへ渡す前に勝手に短縮しない。構造的な冗長さの整理では値・対応・順序の保持を、戦略的な外部化では本人の手掛かりと実際の再取得を確かめ、どちらも整理後の理解と利用を観察する。圧縮率の目標へ収めるために意味を捨てず、あまり縮まらない記録もあると認める。L1以降を旧設計から自動的に決めない。

### 親の文脈とキャッシュを共有する入口

現compactorは親のPromptContextを使わず、別のsystem/instructionsと対象1バッチを文字列化したuser messageを作り、toolsを送らない。同じモデルが選ばれても、親の長い履歴の共通prefixをそのまま再利用できる構造ではない。画像等の省略だけの問題ではない（M02）。

OpenAIの公式仕様では、キャッシュ再利用はsystem等・tools・履歴を含むrendered prefixの一致に依存する。途中の変更はそこから後の再利用を妨げ、同じキーを付けるだけでは解消しない。toolsを制限する場合も定義を保つ方法がある。[OpenAI Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)

設計上は、親の実際の文脈を共通入力として保ち、記憶整理の指示を後に足すことを出発点にする。モデル設定やprovider固有の継続情報も含め、実際の送信内容で一致を確かめる。APIによるKV状態の直接fork機能があるという主張ではない。ヒット率は計測が必要であり、ここまででは実測していない。

整理を行うforkの入力と、整理結果を採用した後の親の入力は別である。後者で古い表現を置き換えれば、変更箇所以後のprefixは変わり得る。その必要な更新と、整理前から親の文脈を別物へ変える無駄を区別する。

## 設計を検討し続けるための題材

以下は私が提案する観察の題材である。ユーザーが明示した記憶整理の要件を確かめるものと、上記の設計仮説を検討するものを含み、一括して必須の受入条件にはしない。

- 過去の行き違いに似た場面で、自分から関連する経験を思い出し、違いも見て行動を変える。
- 当時は用件と関係なかった短い会話が、後の共同作業で意味を持つ。本人がその接点へ戻れる。
- 同じ出来事について、新しい説明を聞いて理解を改める。過去の誤解を相手の事実として固定しない。
- 二人の秘書が同じ場を経験した後、それぞれの立場から振り返る。共有事実と本人の解釈を区別する。
- 冗長なツール記録の整理後も、見た資料・繰り返した失敗・未確認事項・人の言葉のニュアンスを扱える。
- 本人が詳細を外部へ預けた後も、何をどこから取り戻せるかを把握し、必要な場面で自分から読み返せる。
- 記憶整理をforkで進めている間に親へ訂正が届き、整理結果を適用してもその訂正と新しい経験を保つ。
- 自己修正についての設計仮説として、指摘される前に目的と成果のずれを発見し、記憶の中の「自分はできたはず」より実物を優先して修正できるかを調べる。

これらは試験に合格する台詞を決めるための題材ではない。共に過ごして何が成立せず、どこで本人の経験が薄くなるかを見るために使う。結果が想定と違えば、実装だけでなく、この記憶の捉え方も修正する。

## 考察を点検するために参照した研究

ここまでの設計判断が先にあり、以下は裏付けや反証として読む補助資料である。論文間でも対象と測り方が違い、まとめて一つの「人間の記憶の正解モデル」とはしない。

| 点検する単純化 | 一次研究が示す範囲 | Sumiの仕様には直接移せない点 |
|---|---|---|
| 自分についての一般知識があれば、具体的な経験と同じか | 自伝的な語りを比較したLevineらは、出来事・場所・知覚などの詳細と、特定の出来事を離れた知識を区別した。[Levine et al., 2002](https://pubmed.ncbi.nlm.nih.gov/12507363/) | 年齢群の横断比較であり、全記憶が時間とともに同じように要約されるという法則ではない。DBの層を決める根拠でもない。 |
| 同じ人であるために、自己理解も固定するべきか | Libbyらの研究では現在の自己概念と過去の行動の食い違いが、想起時の視覚的な視点に関係した。McAdamsらの縦断研究は自己の語りの連続性と変化を観察した。[Libby & Eibach, 2002](https://pubmed.ncbi.nlm.nih.gov/11831407/)、[McAdams et al., 2006](https://pubmed.ncbi.nlm.nih.gov/16958706/) | 視点の自己報告や物語の内容分析であり、過去の事実を現在に合わせて改変してよいという結論ではない。 |
| 内容が同じなら、どこで知ったかは省いてよいか | 自分で生成した単語と外部提示の単語を区別する実験では、生成時の認知的操作の情報が由来の判断に関わった。[Johnson et al., 1981](https://memlab.yale.edu/sites/default/files/files/1981_Johnson_Raye_Foley_AJoP.pdf) | 単語課題の結果。人間が正確な出典タグを持つという証拠でも、Sumiが由来の取り違えを再現すべきという証拠でもない。 |
| 思い当たる感じを、そのまま確かさと扱えるか | Koriatの実験では、後で正解を再認できそうかという判断が、正誤を含む取り出せた断片と関係した。[Koriat, 1993](https://iipdm.haifa.ac.il/images/publications/Asher_Koriat/1993-Koriat-PR%20FOK.pdf) | 将来の再認についての判断であり、全ての確信やLLMの発話確率を説明するモデルではない。 |
| 約束を覚えるためには、常にその約束を監視し続ける必要があるか | Einsteinらの実験群は、将来の意図の想起に継続監視と自発的な想起という複数の過程が関わり、条件によって異なることを支持した。[Einstein et al., 2005](https://pubmed.ncbi.nlm.nih.gov/16131267/) | 長年の日常の約束を直接調べたものではない。イベント処理とポーリングの使い分けは、Sumi側の設計判断。 |
| 経験を固定件数・固定tokenで切れば、本人にとっての出来事になるか | 連続した映像・物語を使うBaldassanoらの研究では、複数の時間幅のevent構造と想起時の活動との関係が見られた。[Baldassano et al., 2017](https://www.dpmlab.org/papers/Neuron17.pdf) | fMRIとモデルによる分析であり、経験の境界を完全に決める算法ではない。Sumiの層数や圧縮時刻を指定しない。 |
| 同じ場所の文脈を付ければ、必ずよく思い出せるか | 陸上・水中で単語を覚える古典実験は環境一致の効果を報告したが、後の条件の異なる追試では再現されなかった。[Godden & Baddeley, 1975](https://doi.org/10.1111/j.2044-8295.1975.tb01468.x)、[Murre, 2021](https://pure.uva.nl/ws/files/72827653/rsos.200724.pdf) | 一つの追試で文脈効果全体が否定されるわけではない。一方、「場所タグを足せば人間的な想起になる」という万能な説明にも使えない。 |
| 注意の中心から外れることは、情報を失ったことと同じか | Roseらの作業記憶課題では、注意外だが後で必要な情報について、一時的な再活性化を検出した。[Rose et al., 2016](https://pubmed.ncbi.nlm.nih.gov/27934762/) | 限られた短時間の実験であり、生涯の記憶が全て隠れた状態で完全保存されるという証明ではない。 |

確認範囲は論文の抄録または本文の一部。KoriatとMurreは方法・結果・考察、Baldassanoは本文と研究構成も確認したが、全論文の通読・再解析・再現性の系統的評価は行っていない。この表の心理学的指標をLLMに回答させても、同じ測定が成立するとは限らない。

感情や価値、身体や空間との結び付き、長い時間を通じた記憶の変化まで、この限定調査で理解し切ったとは扱わない。その理解は具体的な設計上の問いに戻りながら深める。今ある論文に分類できない経験を、存在しない・重要でないと切り捨てない。
